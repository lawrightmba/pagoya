# Replit Agent Prompts — PTI Signal Expansion (v4.2 → v4.3) — REV 2
### Revised against verified production/dev schema. No code changed yet.

**Changes from REV 1, per schema verification:**
1. `bill_payments` has no `due_date`/`paid_at` — it has `days_from_due` (pre-computed) and `created_at`. Timing features rewritten against `days_from_due`.
2. `cureTimeMedianHours` dropped — not computable at hour granularity, and day-granularity recovery already exists in v4.2 as `recovery_after_miss` (BC dimension). Not rebuilding a duplicate.
3. **Balance reconstruction is now its own scoped stage (1.5)**, not a "generic transform." No `balance-after` column, no signed amount column — inferring credit/debit from `type` (`load_*` vs `spend`/`transfer_send`) is real new logic with edge cases, built once, unit-tested, then reused everywhere balance is needed.
4. Forward-obligation features (`preDueStagingIndex`, `loadToObligationRatio`) re-anchored to `user_billers` (`payment_day`, `typical_amount`, `reminder_days_before`), not `bill_payments`. Explicitly scoped as low-N (3 rows today) — buildable, not yet validatable.
5. Prompt 0 expectations rewritten to not presume the fix landed — dev shows `message_templates` doesn't exist at all, which is a stronger signal than "0 rows in prod." Stage 2 Part C (Paula mechanics) stays skip-by-default until proven otherwise.
6. Timezone normalization required explicitly wherever `bill_payments.created_at` (naive) crosses with `wallet_transactions`/Paula tables (tz-aware).
7. Bill-shock detection pins one canonical amount column instead of choosing among four ambiguous ones.

Also added: a naming-collision guardrail between Stage 1/2 zero-weight fields and Stage 3 quarantined fields, since the isolation regex matches import paths, not arbitrary substrings, and a new field name could accidentally straddle both patterns.

**Execution order: 0 → 1 → 1.5 → 2 → 3 → 4. Do not skip 1.5.**
