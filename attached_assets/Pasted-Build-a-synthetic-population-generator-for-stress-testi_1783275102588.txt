Build a synthetic population generator for stress-testing PTI, entirely 
self-contained — no external services, no API calls, no real user data 
involved.

GOAL: Generate 5,000-10,000 synthetic user profiles across all 39 
PTIDataSnapshot fields, with realistic distributions and correlations 
(not uniform random), then run them through the actual pti.ts scoring 
engine to stress-test it at volume.

REQUIREMENTS:

1. Write a generator script (TypeScript, colocated with the existing 
   derivedSignals.ts work) that produces synthetic PTIDataSnapshot objects.
   Use parameterized statistical distributions per field, not pure random:
   - Correlate related fields realistically (e.g., higher loginDays30 
     should correlate with higher paulaInteractions; higher streakMonths 
     should correlate with lower domStddev; totalLoads should follow a 
     realistic right-skewed distribution, not uniform).
   - Include deliberate edge cases: sparse/cold-start profiles (1-2 data 
     points only), contradictory profiles (high engagement + zero 
     payments), and profiles clustered at every score-tier boundary 
     (just above/below 30, 50, 65, 80).
   - Assign each synthetic user a METADATA-ONLY colonia and 
     declared_income_bucket (NOT fed into scoring, just attached for 
     later bias analysis) — pull realistic distributions from Puerto 
     Vallarta colonia names already used in street_team.colonia.

2. Run every synthetic profile through the real, unmodified pti.ts 
   scoring function. Do not mock or simplify the scoring logic.

3. Produce a report covering:
   - Score distribution across the synthetic population (sanity check: 
     does it look like a plausible bell-ish curve, or does something 
     break/cluster oddly?)
   - Cold-start behavior: do sparse profiles degrade gracefully or throw 
     errors / produce nonsensical scores?
   - Tier boundary behavior: spot-check profiles right at 29/30, 49/50, 
     64/65, 79/80 — confirm clean transitions.
   - Fair-lending adjustment layer: confirm it never exceeds its ±5/±2 
     caps across the full synthetic population.
   - Disparate-impact proxy check: group synthetic scores by the 
     metadata-only colonia/income_bucket fields (NOT used in scoring) 
     and check whether score distributions differ meaningfully across 
     those groups — this tests whether excluded variables are leaking 
     through correlated proxy signals even though not directly scored.
   - Gaming resistance: include synthetic profiles that try to game 
     specific signals (e.g. inflated selfRatio or advanceDays with very 
     low payCount) and confirm existing cold-start gates (payCount >= 2/3) 
     still block them.

4. This is entirely a local/dev-only exercise. Do not write anything to 
   production. Do not use any real user data as a seed — generate 
   everything from hand-specified distributions.

Report back with the full findings, plus flag anything that looks like 
a real bug (not just "interesting data") the same way you've flagged 
issues throughout this project.
