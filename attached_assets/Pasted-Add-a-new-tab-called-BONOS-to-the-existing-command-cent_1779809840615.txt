PART A — THREE NEW ADMIN ENDPOINTS
─────────────────────────────────────────
Add to the existing admin router file:

1. POST /api/admin/bonus-config
   - Accepts: { is_active, bonus_amount, eligible_rep_codes, 
     warning_threshold, block_threshold }
   - Updates signup_bonus_config row id=1 with provided fields
   - Sets updated_at = now()
   - Returns { success: true }
   - Protect with existing admin auth middleware

2. GET /api/admin/rep-flags
   - Returns all rows from rep_velocity_flags
   - Ordered by flagged_at DESC
   - Returns { flags: [...] }
   - Protect with existing admin auth middleware

3. GET /api/admin/bonus-stats
   - Accepts optional query params: range = 'today' | 'week' | 'custom'
     and start_date, end_date for custom range
   - Returns:
     {
       total_bonuses_issued: count of SIGNUP_BONUS wallet_transactions,
       total_bonus_value: sum of amounts,
       by_rep: [ { ref_code, count, total_value } ],
       by_date: [ { date, count, total_value } ]
     }
   - Filter by created_at based on range param
   - Default to 'today' if no range provided
   - Protect with existing admin auth middleware

PART B — BONOS TAB UI
─────────────────────────────────────────
Add "BONOS" as a new tab in the command center tab bar,
styled consistently with existing tabs.

The tab content has three sections:

SECTION 1 — Campaign Toggle (top)
  - Toggle switch: Bonus Active / Inactive
    Shows green "ACTIVO" or grey "INACTIVO"

SECTION 2 — Rep Fraud Log (middle)
  - Header: "Alertas de Velocidad"

  - BLOCK rows: red background

  - Refreshes on tab load via GET /api/admin/rep-flags

SECTION 3 — Campaign Stats (bottom)
  - Header: "Estadísticas de Bonos"

    Custom shows two date inputs (start, end)

  - Refreshes when range selector changes
