    <h2>System Architecture</h2>

    <h3>Stack Layers (Top → Bottom)</h3>
    <div class="arch-stack">
      <div class="layer layer-1">
        <div class="layer-label">User Layer</div>
        <div class="layer-content">
          <strong>WhatsApp (via Twilio)</strong>
          <span>Inbound webhook → POST /api/whatsapp-agent · Twilio Business Account · Phone number: dedicated PagoYa line</span>

      </div>
      <div class="layer layer-2">
        <div class="layer-label">Agent Layer</div>
        <div class="layer-content">
          <strong>Claude Sonnet (Anthropic API) — NLU + Orchestration</strong>
          <span>Intent classification · Entity extraction · Multi-turn session state · Spanish language processing</span>
        </div>
      </div>
      <div class="layer layer-3">
        <div class="layer-label">Logic Layer</div>
        <div class="layer-content">
          <strong>PagoYa Express Backend (Replit VM)</strong>
          <span>Session manager · User lookup · Commission attribution · Confirmation flows · Receipt generation</span>
        </div>
      </div>
      <div class="layer layer-4">
        <div class="layer-label">Payment Rails</div>
        <div class="layer-content">
          <strong>SIPREL (bills) · Conekta (card top-up) · Digital Femsa/OXXO (cash-in)</strong>
          <span>Existing integrations — agent calls same endpoints as web app</span>
        </div>
      </div>
      <div class="layer layer-5">
        <div class="layer-label">Data Layer</div>
        <div class="layer-content">
          <strong>Drizzle ORM → PostgreSQL (Replit)</strong>
          <span>Users · Transactions · Sessions · Rep attribution · Colonia tags</span>
        </div>
      </div>
    </div>

    <h3>New Endpoint Required</h3>
    <div class="code-block">
<span class="comment">// New route: POST /api/whatsapp-agent</span>
<span class="comment">// Receives Twilio webhook, routes to agent orchestrator</span>

{
  <span class="key">from</span>: <span class="str">"whatsapp:+52XXXXXXXXXX"</span>,
  <span class="key">body</span>: <span class="str">"Paga mi CFE"</span>,
  <span class="key">profileName</span>: <span class="str">"Juan"</span>,
  <span class="key">waId</span>: <span class="str">"52XXXXXXXXXX"</span>  <span class="comment">// used as session + user key</span>
}

<span class="comment">// Session store: Redis or in-memory Map keyed by waId</span>
<span class="comment">// TTL: 30 minutes of inactivity resets conversation</span>
    </div>

    <h3>Agent Orchestrator Logic</h3>
    <div class="flow">
      <div class="flow-step">
        <div class="flow-number">1</div>
        <div class="flow-content">
          <strong>Inbound Message Received</strong>
          <p>Twilio webhook fires → extract waId, body, profileName → lookup user in DB by phone number</p>
        </div>
      </div>
      <div class="flow-step">
        <div class="flow-number">2</div>
        <div class="flow-content">
          <strong>Session Hydration</strong>
          <p>Load existing conversation history from session store. If new user → set onboarding state. If returning → load their services (CFE account #, TELMEX #, etc.)</p>
        </div>
      </div>
      <div class="flow-step">
        <div class="flow-number">3</div>
        <div class="flow-content">
          <strong>Claude API Call (Intent + Entity Extraction)</strong>
          <p>Send full conversation history + system prompt. Claude classifies intent, extracts entities (service name, amount, account number), generates reply in Spanish.</p>
        </div>
      </div>
      <div class="flow-step">
        <div class="flow-number">4</div>
        <div class="flow-content">
          <strong>Action Execution</strong>
          <p>If intent = confirmed payment → call SIPREL/Conekta/OXXO endpoint. Await result. Handle failures gracefully with fallback messaging.</p>
        </div>
      </div>
      <div class="flow-step">
        <div class="flow-number">5</div>
        <div class="flow-content">
          <strong>Reply + Receipt</strong>
          <p>Send WhatsApp confirmation via Twilio. Log transaction with rep_code attribution. Update session history. Commission auto-applied if rep referral present.</p>
        </div>
      </div>
    </div>

  <section id="risks" class="section">
    <h2>Risks & Mitigations</h2>

    <div class="card">
      <div class="card-title"><div class="icon icon-coral">⚠️</div>Twilio WhatsApp Approval Delay</div>
      <p><strong>Risk:</strong> Meta/Twilio business account verification for WhatsApp takes 2–4 weeks.<br>
      <strong>Mitigation:</strong> Start sandbox approval immediately — Day 1. Sandbox works for testing with registered numbers. Build against sandbox, flip to production number once approved.</p>
    </div>

    <div class="card">
      <div class="card-title"><div class="icon icon-coral">⚠️</div>NLU Misclassification in Spanish</div>
      <p><strong>Risk:</strong> Regional slang, abbreviations ("cfe", "tele", "la luz") may not classify cleanly.<br>
      <strong>Mitigation:</strong> Build a slang dictionary into the system prompt. Log every unrecognized intent to a review queue. Claude handles ambiguity well with good few-shot examples in the prompt.</p>
    </div>

    <div class="card">
      <div class="card-title"><div class="icon icon-gold">⚠️</div>Conekta Not Yet Live</div>
      <p><strong>Risk:</strong> Card top-up in WhatsApp requires live Conekta keys — onboarding at panel.conekta.com still pending.<br>
      <strong>Mitigation:</strong> Launch agent without card top-up (Week 1–2). Add it in Week 3 once Conekta is live. SIPREL + OXXO cover 80% of use cases already.</p>
    </div>

    <div class="card">
      <div class="card-title"><div class="icon icon-purple">⚠️</div>Session Memory Cost at Scale</div>
      <p><strong>Risk:</strong> In-memory session store won't survive Replit VM restarts.<br>
      <strong>Mitigation:</strong> Start with in-memory (fine for MVP). Add Redis or Replit KV before launch when concurrent sessions exceed ~50.</p>
    </div>

    <div class="callout callout-warn">
      <div class="callout-icon">🔒</div>
      <div class="callout-body">
        <strong>Critical: Never execute payments without explicit confirmation</strong>
        <p>FSM must always route through a confirmation step before calling any payment rail. User must type "SÍ" or "CONFIRMAR" — never auto-execute on intent alone. This is both a UX and compliance requirement.</p>
      </div>
    </div>
