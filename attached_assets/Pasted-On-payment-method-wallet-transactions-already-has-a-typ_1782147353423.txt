1C. SERVER-SIDE PARSING UTILITY — create lib/services/deviceParser.ts:

Parse User-Agent string + optional PWA hint header.
Export a single function:

  parseDevice(userAgent: string, isPwa?: boolean): DeviceProfile

  interface DeviceProfile {
    os: string;           // 'iOS' | 'Android' | 'Windows' | 'macOS' | 'Linux' | 'Other'
    osVersion: string;    // e.g. '17.4', '14', '11'
    model: string;        // e.g. 'iPhone 15', 'Samsung SM-A055', 'Motorola Moto G', 'Unknown'
    type: string;         // 'mobile' | 'tablet' | 'desktop'
    accessMode: string;   // 'pwa' | 'browser'
  }

Parsing rules:
- iOS: detect 'iPhone' (mobile), 'iPad' (tablet). Extract version from 'OS X_Y_Z'.
  Model detection: iPhone15,x → 'iPhone 15', iPhone14,x → 'iPhone 14', etc.
  If model not mappable, return 'iPhone (Unknown Model)'.
- Android: detect 'Android'. Extract version from 'Android X.Y'.
  Look for Samsung SM-*, Motorola moto*, Xiaomi, LG, Huawei in UA string.
  Extract model identifier as-is if found, else 'Android Device'.
- Desktop: Windows NT → 'Windows', Mac OS X (non-mobile) → 'macOS',
  Linux (non-Android) → 'Linux'.
- isPwa: if true, set accessMode = 'pwa'. Else 'browser'.
- osVersion: extract best available semver string, or empty string if unparseable.

After crediting the wallet, detect the load method and update users:

  const method = mapTransactionTypeToMethod(tx.type); // 'oxxo'|'spei'|'card'
  if (!method) return; // unmapped type — skip silently

  -- Increment the right counter:
  UPDATE users SET
    oxxo_load_count = oxxo_load_count + (method === 'oxxo' ? 1 : 0),
    spei_load_count = spei_load_count + (method === 'spei' ? 1 : 0),
    card_load_count = card_load_count + (method === 'card' ? 1 : 0),
    first_load_method = COALESCE(first_load_method, method),
    last_load_method  = method,
    first_spei_load_at = CASE 
      WHEN method = 'spei' AND first_spei_load_at IS NULL 
      THEN NOW() ELSE first_spei_load_at END,
    load_method_updated_at = NOW()
  WHERE id = user_id;

Two things to flag before you run this:
On device model: the UA string on Android is notoriously messy — you'll get clean Samsung SM-A055M but also garbage strings. The parser I've spec'd handles this gracefully (logs unknown, doesn't crash), but don't expect 100% model coverage on Android. iOS is much cleaner.
On the bancarization event (first_spei_load_at): this is your single most valuable signal for a B2B PTI pitch. A user who arrives cash-only (OXXO) and migrates to SPEI while on your platform is a demonstrable financial inclusion outcome. That's a story Kueski, a SOFIPO, and Accion Venture Lab all want to hear quantified.
