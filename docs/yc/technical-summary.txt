2. Agentic AI — Paula

Paula is a Claude-powered AI agent (claude-sonnet-4-5) running a tool-use loop across two simultaneous channels: WhatsApp (inbound) and an in-app floating widget on every product page. She is not a chatbot — she takes real actions against live user data and personalizes every response using the user's WhatsApp display name.

Tool Set (live today)

Tool                     | What It Does
-------------------------|--------------------------------------------------------------
get_wallet_balance       | Returns exact MXN balance in real time from the wallets table
get_payment_history      | Retrieves and narrates recent transactions in natural Spanish
get_pending_oxxo         | Checks if a cash deposit voucher is still pending confirmation
get_loyalty_points       | Returns current points balance, lifetime total, tier (Bronce/Plata/Oro), and points to next tier
get_deposit_instructions | Returns step-by-step funding instructions for OXXO, SPEI, or card — whichever the user asks about
prepare_bill_payment     | Validates service + reference + balance, stages payment with fee-inclusive summary for 2FA confirmation — handles both bill payments and digital gift card purchases
escalate_to_support      | Hands off to human agent via WhatsApp with full conversation context

Deployment Architecture

- WhatsApp inbound: any message routes through the Paula agent loop. Paula greets users by their WhatsApp display name on first contact. First-contact messages screened for rep referral codes.
- In-app widget: persists across every screen with localStorage session memory, typing indicator, escalation banner.
- Post-payment hook: app auto-opens Paula's chat 4 seconds after payment with pre-filled context — turns a receipt into a retention event.
- AI bill autofill: home screen natural-language input parses 'CFE 350 pesos' and pre-fills service, amount, and reference in one shot via Claude.
- Explicit confirmation screen (shipped June 1, 2026): before any OTP is issued, Paula sends a structured confirmation card showing biller/product name, reference number, exact amount, total charge inclusive of the $25 MXN fee, payment method, and available wallet balance. User must reply SÍ or CANCELAR — ambiguous input loops back to the confirmation prompt. Cancel fires immediately at any point in any flow.

Contextual Paula Hints (live as of May 2026)

Paula surfaces inline at 6 high-friction points — not as a chat prompt, but as a contextual nudge that pre-loads her with the exact question the user is most likely stuck on.

- Registration — CURP field: "¿No sabes tu CURP? Paula puede ayudarte a encontrarla."
- OTP screen: troubleshooting prompt after a failed or expired code.
- Payment form — reference number field: "¿Dónde encuentro mi número de referencia?" — pre-loaded with biller context.
- Payment review — fee line: "¿Por qué hay una comisión de $25 MXN?"
- Cash load screen: step-by-step OXXO deposit guidance.


3. Payment Infrastructure

Wallet Architecture

Every user has a wallets row linked by phone. All debits and credits are atomic DB transactions using a conditional UPDATE ... WHERE balance_mxn >= amount RETURNING id pattern. If zero rows returned, the transaction is rejected with INSUFFICIENT_BALANCE before any external API call. No partial states, no race conditions.

Transaction Type      | Source                     | Badge Color | Status
----------------------|----------------------------|-------------|-----------------------------------------------
load_oxxo             | Digital Femsa barcode      | Coral       | pending → completed via webhook
load_card             | Stripe live card charge    | Purple      | completed on payment_intent.succeeded webhook
load_spei             | SPEI inbound transfer      | Blue        | completed on bank webhook
bill_pay              | SIPREL / Evoluciona        | Red debit   | atomic with wallet debit
gift_card             | SIPREL / Taecel PIN        | Red debit   | Stripe charge + SIPREL PIN sequenced; decoupled for integrity
SIGNUP_BONUS          | Street team referral       | Green       | credited post OTP verification
FREE_TOKEN            | Auto-issued at signup      | Green       | 3 tokens per new user; each waives $25 MXN fee atomically
p2p_send/p2p_receive  | User-to-user transfer      | Orange      | atomic debit + credit

Bill Pay Rail

- Primary: SIPREL — 20+ billers including CFE, Telmex, Telcel, IZZI, Sky, and streaming services
- Fallback: Evoluciona Movil — auto-failover if SIPREL returns an error
- Fee: $25 MXN flat per transaction, deducted atomically from wallet
- Daily AML cap: $50,000 MXN per user per day enforced at the route layer before any provider call
- Loyalty: 1 pt per $10 MXN paid; Bronze/Silver/Gold multipliers; redeemable for wallet credit or fee waiver token

5. Street Team Referral & OTP Onboarding

Reps recruit users in the field with unique QR codes. The signup flow is fully gated by WhatsApp OTP before any wallet or user record is created.

Step         | What Happens                                              | Fraud Guard
-------------|-----------------------------------------------------------|-------------------------------------------------------
Form         | Name, phone (E.164), CURP (optional), colonia, ref_code   | Phone duplicate check before OTP; CURP dupe check skipped if blank
OTP          | 6-digit code via Twilio WhatsApp, 5-min TTL, 3-attempt limit | generateOTP resets on resend; max_attempts blocks without expiring session
Bonus Credit | Wallet credited $25–50 MXN via SIGNUP_BONUS + 3 free transaction tokens | Idempotency lock on signup_bonus_claimed; rep velocity check (warn @10/hr, block @20/hr)

7. KYC, Security & Compliance

- CURP — optional at signup (June 2, 2026); regex validation live; when provided, RENAPO stub enforces Nivel 2 limit of $24,000 MXN/month (vs. $6,000 unverified). RENAPO API credentials unlock full CNBV Nivel 2 compliance conversations.
- Belvo API integration: aggregation/KYC (7 endpoints) + Direct Debit (11 endpoints) — deployed, awaiting Belvo production credential approval
- JWT authentication + bcrypt password hashing throughout
- Per-landlord CLABE configuration with lease ownership validation (PagoSeguro)
- LFPDPPP-compliant Privacy Notice and Terms of Service live at pagoyamx.com
- HTTP→HTTPS redirect middleware, httpOnly session cookies, secure flag in production
- Immutable audit log via Postgres-level triggers (PagoSeguro payment events + rep operations)
- UptimeRobot monitoring on both domains
- Rate limiting: payments/transfers 20 req/15 min; OTP 5/15 min; wallet loads 10/15 min — Express middleware layer
- AML daily cap: $50,000 MXN per user per day on bill payments, enforced via DB aggregate before provider call
- Atomic wallet debit: conditional SQL UPDATE eliminates race condition across all debit paths (bill pay, gift card, P2P transfer, wallet load)
- Admin route protection: ADMIN_TOKEN env var required for command center and all admin APIs
